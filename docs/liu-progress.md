## 2026-11-17：无故障诊断与 GET 连接恢复修正

诊断批次 `20261117-io-diagnostic` 的文件/分享容器重建成功，分享 verify 7 项测试通过。无故障探测共 1,062 条记录：1,061 成功、1 次个人下载 503，于第 116 个 tick 检测后停止。请求耗时约 33 ms；文件服务在 UTC 07:17:08.011 记录 `storage_failure operation=open errorType=IOException`。这定位到 MinIO 对象流打开阶段，支持排除认证服务依赖及探针超时；具体网络断开原因未由该分类日志给出。

修正为只对 GET 下载启用 OkHttp 连接失败恢复，上传与控制操作保持原 transport 配置；已返回对象流不在应用层重放。新增两个文件服务测试，模拟复用连接在响应头前断开，以及部分正文断开后不重放。此行为参考 [OkHttp Builder 文档](https://javadoc.io/static/com.squareup.okhttp3/okhttp/3.5.0/okhttp3/OkHttpClient.Builder.html)，是否消除本环境基线异常，以新诊断及正式批次结果为准。

同时修正探针关联：原探针自发 ID 会被 Nginx 重写，旧异常按时间/方法/状态与服务日志匹配；现在 Nginx 回传其生成的 X-Request-Id，探针优先记录实际服务 ID。Python 工具 24 项回归通过。本会话尝试宿主 Maven 验证时网络被系统拒绝（Permission denied: getsockopt），因此新增 Java 测试尚待用户本机 Docker 构建执行，不能宣称通过。

派生分析另修正故障边界：计划在 t0 之前、实际在 t0 之后发出的失败请求仍计入首次失败；t1 取实际失败回包时间，另列失败请求的发出时间。成功率窗口继续按计划 tick 归属，口径在报告中说明。回归覆盖这种调度滞后边界。
