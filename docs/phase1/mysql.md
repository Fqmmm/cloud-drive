# mysql 需求文档

负责人：B。A 提供认证和分享建表脚本，C 接入 Compose，D 验证持久化。关联：[总体方案](../plan.md)、[持久化实验](../phase2/04-persistence.md)。

## 1. 容器与数据库布局

使用一个 MySQL 容器，创建 auth_db、file_db、share_db 三个逻辑数据库。三个业务服务通过容器网络连接 mysql:3306。默认不发布宿主机 3306，调试时通过覆盖配置绑定本机地址。

| 数据库 | 账号 | 表归属 | 维护人 |
|---|---|---|---|
| auth_db | auth_user | 用户、账户 | A |
| file_db | file_user | 文件、目录、物理对象映射、固定配额、对象清理状态 | B |
| share_db | share_user | 个人分享记录 | A |

root 用于初始化和运维，不写入应用连接配置。三个应用账号只授权自己的数据库，不具备跨库读取、账号管理或全局管理权限。密码通过环境配置注入，提交 `.env.example` 时使用占位值。

## 2. 表结构与约束

统一使用 utf8mb4、InnoDB 和明确的时间保存规则。文件名涉及 Unicode，记录所选排序规则下的大小写和重名行为。三个库之间保留 ID 引用，跨服务外键和联表查询通过接口替代。

认证库约束账户名、邮箱唯一；文件库约束用户配额唯一及活动同目录名称唯一；分享库约束 shareToken 唯一。业务库内需要的索引、外键和状态字段由对应负责人写进 SQL。对软删除和名称复用的处理需给出可执行方案，不用无法区分活动记录的简单唯一键代替。

用户 ID、账户 ID、文件 ID 的类型统一为现有 Java Long 对应的整数类型，前端序列化方式由 A、B 联调确认，避免超出 JavaScript 安全整数范围时发生精度丢失。

## 3. 初始化与迁移

首版部署优先使用新建课程数据卷，建立清晰的演示数据。原数据库如需迁移，先备份，再按表归属导入并校验 ID 引用。原包含团队、Flowable 和管理员数据的整库脚本不直接挂到新的初始化目录。

建议初始化脚本顺序：

1. 创建三个逻辑数据库。
2. 创建数据库账号并授权，从容器环境读取实际密码。
3. 导入 auth、file、share 各自表结构及必要基础数据。
4. 执行版本记录和最小查询，初始化失败时输出明确日志并终止。

MySQL 的 SQL 初始化文件不会自动替换 `${...}` 变量。动态账号密码使用受控初始化脚本读取环境并正确转义，或由迁移工具参数化创建；禁止把未展开的占位字符串当成实际密码。初始化脚本只在全新数据目录执行，已有数据卷升级使用显式版本迁移脚本。迁移脚本注明源版本、目标版本、执行顺序和备份要求。

自动初始化后即可注册用户，无需手工执行 SQL。演示账号通过 API 创建，避免仓库中出现明文业务密码。

## 4. Compose 与持久化

配置 MYSQL_ROOT_PASSWORD、三个应用数据库密码、时区及命名卷 mysql_data，将数据卷挂到 `/var/lib/mysql`。记录选定镜像版本和 digest，不沿用未验证的版本标签。

健康检查在容器内执行带认证的简单查询，确认初始化完成且目标库存在。实际使用的客户端与脚本应随镜像或挂载提供。健康检查通过后应用才能开始数据库依赖初始化。应用本身仍配置连接重试和超时。[Compose 启动依赖](https://docs.docker.com/compose/how-tos/startup-order/)

C 负责 Compose 依赖声明，B 提供数据库检查命令、脚本挂载路径和配置字段。容器重建时使用同一个项目名和数据卷，避免因项目名变化误接入新卷。

## 5. 备份与恢复接口

B 向 D 提供三库备份、恢复到新卷、记录数与关键关联检查的方法。备份由具备足够权限的运维账号执行，数据集停止业务写入后导出，参数和客户端版本一并记录。备份文件不包含环境密码，日志不输出完整连接凭证。

对 MySQL 与 MinIO 联合恢复采用停写窗口：先停止三个业务服务的写入，再导出数据库和对象，记录同一批次号。数据库备份能恢复记录，实际文件还需要对应 MinIO 对象。恢复后验证用户登录、元数据、分享和文件 SHA-256。

基础持久化实验保留卷重建容器；备份恢复实验使用独立项目和新卷，原数据保留供比较。

## 6. 验收与交付

| 检查 | 通过条件 |
|---|---|
| 全新部署 | 自动创建三库、账号和表，应用可直接注册上传 |
| 权限 | 每个应用账号只能访问所属数据库 |
| 约束 | 重复注册、并发配额初始化和重名写入受约束保护 |
| 重建 | 保留 mysql_data 重建后，用户、文件和分享记录一致 |
| 升级 | 初始化与已有卷迁移路径均有说明和执行记录 |
| 故障恢复 | MySQL 恢复后应用可重新连接，无需重新注册或导入 |

交付初始化目录、迁移 SQL、版本记录、权限清单、健康检查、数据卷说明、备份恢复步骤和验收结果。
