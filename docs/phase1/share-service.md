# share-service 需求文档

负责人：肖国扬，与 狄东琛 联调文件内部接口。关联：[总体方案](../plan.md)、[文件服务](file-service.md)、[前端](frontend.md)。

## 1. 分享生命周期

用户登录后选择自己的一份普通文件创建分享。创建请求包含 `fileId`、`accessType`、`expireDays`。`accessType` 只接受 0（公开）和 1（提取码）；`expireDays` 只接受 1、7、30 或 null（永久）。提取码由服务端安全随机生成，固定为六位数字（包含前导零），请求与响应均使用字符串；创建成功时返回一次，数据库保存带盐强散列。

分享 token 使用密码学安全随机数，至少 128 位随机性，并有唯一约束。分享记录保存创建者 userId、文件 ID、创建时文件名、访问方式、提取码散列、到期时间、状态和时间戳。服务端统一以 UTC 保存和比较时间，前端按本地时区展示。

创建前通过文件服务确认文件属于当前用户、处于活动状态且为普通文件。文件服务不可用时返回 503，创建失败；不将“未完成检查”当作通过。

分享创建后，用户可列出自己的分享并取消。取消只修改 share_db，本地立即生效；重复取消幂等。匿名访问每次检查分享是否存在、已取消、已过期，并通过文件服务检查文件状态。文件删除后访问返回资源失效，历史分享记录可保留供本人查看。

## 2. 对外 API

| 方法与路径 | 输入 | 输出/行为 |
|---|---|---|
| `POST /api/v1/shares` | JWT；`fileId, accessType, expireDays` | `id, shareToken, shareUrl, extractCode, expireTime` |
| `GET /api/v1/shares` | JWT | 本人全部分享记录，包含未取消、已取消和已过期记录及文件名快照 |
| `DELETE /api/v1/shares/{id}` | JWT | 取消本人分享 |
| `GET /api/v1/s/{token}` | 公开 | 分享可用性、是否需要提取码；受保护分享不泄露文件详情 |
| `POST /api/v1/s/{token}/verify` | `{extractCode}`，公开分享可为空 | 校验后返回文件名、大小、有效期 |
| `POST /api/v1/s/{token}/download` | `{extractCode}`，公开分享可为空 | 再次校验并返回文件流 |
| `GET /health/live`、`GET /health/ready` | 容器探测 | 存活/依赖就绪 |

现有匿名下载使用 GET，本方案将其改为 POST，前端同步更新，提取码放在请求体。校验接口不签发长期下载权限，下载接口自身完成全部验证，避免跳过 verify 直接下载。分享 URL 指向 frontend，按前端实际 hash/history 路由生成，不包含服务名或 MinIO 地址。

JSON 协议沿用 `{code, msg, data}`。分享错误按下表返回；业务码使用字符串，由公共协议统一定义。匿名提取码错误不用 401，避免触发前端登录过期跳转。

| 情况 | HTTP 状态 | code | 前端提示 |
|---|---|---|---|
| 分享记录不存在 | 404 | SHARE_NOT_FOUND | 分享不存在 |
| 源文件已失效或不可见 | 404 | SHARE_FILE_UNAVAILABLE | 文件已失效 |
| 分享已取消 | 410 | SHARE_CANCELLED | 分享已取消 |
| 分享已过期 | 410 | SHARE_EXPIRED | 分享已过期 |
| 提取码缺失或错误 | 403 | SHARE_CODE_INVALID | 请输入正确提取码 |
| 错误提取码尝试过多 | 429 | SHARE_CODE_RATE_LIMITED | 尝试过于频繁，请稍后再试 |
| 下游依赖暂不可用 | 503 | DEPENDENCY_UNAVAILABLE | 服务暂不可用，请稍后重试 |

检查顺序为分享存在、取消、过期、提取码、文件可用性；同时满足多个失效条件时按该顺序返回，受保护文件的详情与状态在提取码验证后读取。网关自身的 502/504 等响应由前端通用错误处理兜底，无需改写为上述业务码。

## 3. 服务间协作

创建分享：验证 JWT → 读取当前 userId → 调用 `GET /internal/v1/files/{id}?ownerId=...` → 检查普通文件与活动状态 → 写入 share_db。

匿名下载：查询分享 → 检查有效期和提取码 → 调用文件服务检查当前文件状态 → 使用记录中的 ownerId 和 fileId 调用内容接口 → 将流转发给浏览器。所有下游请求携带 `X-Internal-Token`。内部凭证只在容器间传递，客户端无法指定下载的 ownerId 或替换记录中的 fileId。

下载采用流式转发，避免整份文件加载到 Java 堆；浏览器断开时关闭下游连接。查询连接/读取超时基线为 3/5 秒，文件读取超时为 120 秒。只对可安全重试的元数据读取安排有限重试，已经开始输出的下载不自动重放。取消影响后续请求，已经开始的下载按当前连接生命周期结束。

## 4. 数据与代码迁移

share_db 只保存分享记录，不保存文件正文，不直接访问 file_db/auth_db。沿用 sys_share 时只保留个人分享路径；团队字段按迁移方案保留为空或移除。删除 `TeamPermissionService`、团队 Mapper 和分享 SQL 中对 team_space、team_member 的子查询。

原 `ShareServiceImpl` 直接使用 `SysFileMapper` 和 `FileObjectService`，需替换为文件服务 HTTP 客户端。移除目录树访问、团队分享、SSE 进度和会员限速逻辑。本人分享列表使用创建时的文件名快照，不为每条记录实时查询文件服务；列表状态按分享记录显示“未取消”“已取消”“已过期”，不承诺实时展示源文件删除状态。文件重命名不改变分享目标，下载采用当前文件名；真正访问时重新校验文件状态。shareUrl 按公开入口和 token 生成，无需在数据库重复保存整条 URL。

同一用户可对同一文件创建多个分享，取消按分享 ID 生效。数据库索引至少覆盖 shareToken 唯一查询、创建者列表和到期时间。提取码散列不写入响应。提取码仅对错误尝试计数和限流，verify 与 download 共用同一计数。按每个分享 token、每个实例统计，默认窗口为 60 秒、允许 5 次错误，超过后错误请求返回 429 与 SHARE_CODE_RATE_LIMITED，窗口结束后重置。公开分享和正确提取码请求不受错误次数限制。参数可配置，E1/E3 保持既有正确请求，不增加限流测量场景。双副本实验记录其为每实例限制；本课程版本不提供全局累计锁定。

## 5. 部署、状态与可观测性

容器内 8080，连接 `mysql:3306/share_db`，数据库用户 share_user。配置 `FILE_SERVICE_URL=http://file-service:8080`、PUBLIC_BASE_URL、前端路由模式、内部凭证和 JWT 参数。提供 `APP_VERSION`、实例标识用于独立更新和扩容观察，可通过业务响应头 `X-App-Version`、`X-Instance-Id` 返回。

分享业务不依赖认证服务的实时连接。就绪检查确认 share_db 可用；文件服务健康作为依赖指标单独记录，由具体业务请求决定是否返回降级错误。文件服务停止时，本人分享列表与取消仍可工作，创建、详情验证和下载受影响。存活检查只检测进程。实例中不保存决定分享有效性的必要会话状态，各副本共享数据库和配置。日志记录请求 ID、结果类别、下游耗时及实例 ID，过滤完整分享 token、提取码和鉴权头。

实验三需要一个受控的主进程异常退出入口。肖国扬 实现 `POST /internal/test/exit`，仅在 `EXPERIMENT_FAULTS_ENABLED=true` 时启用，校验内部凭证后记录事件并以非零码终止 JVM。默认关闭，Nginx 拒绝转发；具体注入与收尾见[故障实验](../phase2/03-failure-recovery.md)。

## 6. 验收

- 自有普通文件可创建分享；他人文件、目录、不存在和已删除文件均被拒绝。
- 公开分享匿名可下载；受保护分享在缺码或错码时无法获取文件正文和详情。
- verify 成功后改用错误提取码调用 download，仍被拒绝。
- 用户只能查看、取消自己的分享，重复取消保持相同业务结果；取消记录仍在本人列表中显示“已取消”。
- 过期、取消或删除源文件后，新下载请求失败；文件服务恢复后有效分享可重新访问。
- 下载 SHA-256 与源文件一致；响应不包含 MinIO 凭证或内部地址。
- 使用 share_user 查询 file_db/auth_db 被拒绝；移除 Redis、Flowable 后能独立启动到预期状态。
