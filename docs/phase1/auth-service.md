# auth-service 需求文档

负责人：肖国扬。该容器负责身份认证和基础用户资料。关联：[总体方案](../plan.md)、[文件服务](file-service.md)。

## 1. 业务要求

注册接收 `accountName`、`password`、`nickname`、`email`；沿用字段 `accountType` 时只接受 `personal`。注册校验沿用[全系统功能需求](../functional-requirements.md)：账户名 3—32 位字母数字下划线并按小写归一，密码 8—64 字符，昵称 1—32 字符。账户名与邮箱设置唯一约束，密码使用现有 PasswordEncoder 的强哈希实现，密码散列不出现在响应中。参数规则在前后端一致，明确长度、必填项和邮箱格式。

用户和账户记录在 auth_db 的同一本地事务中创建。重复账户名或邮箱返回明确错误，并由数据库唯一约束兜底。注册完成后用户可以登录，文件配额由文件服务首次使用时创建。

账户名按小写归一后保存和判重，登录时使用相同规则归一后查找账户，再校验密码及账户状态，成功返回 JWT 和基础用户信息。错误账户和密码使用统一的凭证错误信息。退出登录由前端删除凭证；当前版本采用短期有效 JWT，默认有效期 2 小时，不提供刷新令牌和即时吊销。

基础用户接口只返回用户 ID、账户 ID、昵称、账户名、邮箱等必要字段。会员、团队配额、私密空间状态从此响应移出，前端分别处理文件配额。

## 2. 对外接口与协议

| 方法与路径 | 输入 | 成功输出 | 认证 |
|---|---|---|---|
| `POST /api/v1/auth/register` | 注册 JSON | 空 data | 公开 |
| `POST /api/v1/auth/login` | `accountName, password` | `token, userId, accountId, nickname, accountName` | 公开 |
| `GET /api/v1/users/me` | Bearer JWT | 基础用户资料 | 必须 |
| `GET /health/live` | 无 | 进程存活状态 | 容器内探测 |
| `GET /health/ready` | 无 | 数据库就绪状态 | 容器内探测 |

业务 JSON 沿用 `{code, msg, data}` 和成功码 `00000`。参数错误返回 400，登录失败或无效 JWT 返回 401，唯一性冲突返回 409，数据库暂不可用返回 503。状态码与业务码映射由 肖国扬 汇总，三服务使用同一约定。

## 3. JWT 与公共代码

肖国扬 维护最小的认证公共模块或受版本管理的公共代码，包含 JWT 验证、身份读取和必要错误处理。各应用独立构建、独立启动，公共模块中不包含业务 Service、Mapper 或数据库连接。

JWT 使用 HS256，`JWT_SECRET` 至少 32 字节且由环境注入，签发并校验 `sub/userId`、`accountId`、`iat`、`exp`、`iss`、`aud`。明确接受的算法和时钟偏差。用户名仅用于展示，文件权限以已验证的用户 ID 为准。文件、分享服务在本地验证 JWT，不查询 auth_db、不逐请求回调认证服务。

`INTERNAL_API_TOKEN` 与 JWT 密钥分开配置。浏览器提供的用户 ID 请求头不作为身份依据。健康响应只包含简要状态，密钥和连接信息不返回。

## 4. 数据与现有代码迁移

| 归属 | 处理 |
|---|---|
| 用户、账户表 | 迁入 auth_db，保持全局用户 ID 和账户 ID 的含义一致 |
| 用户配额表 | 归 file_db，注册不调用 QuotaService |
| 基础用户资料 | 精简现有 UserService 的聚合响应 |
| Security 配置 | 各服务只加载自身端点需要的过滤器与授权规则 |

重点修改原 `AuthServiceImpl.register()` 中的配额初始化，以及 `UserServiceImpl` 对会员、团队配额和私密空间的依赖。删掉相关 Bean 后检查组件扫描、配置绑定和测试，保证单独启动认证服务时只需要 MySQL。

## 5. 部署与故障行为

使用容器内 8080，连接 `mysql:3306/auth_db`，账号为 `auth_user`。配置包括数据库连接、JWT 密钥与有效期、发行者与受众、HTTP 端口。数据库账号权限限定 auth_db。

Dockerfile 使用 Java 17 的已验证镜像版本，支持从源码构建，运行命令使用 exec 形式。就绪探测确认数据库可查询，存活探测不检查外部服务。数据库连接与查询设置有限超时，失败后能在数据库恢复时重新获取连接。

认证服务停止时新登录不可用；文件、分享服务继续验证尚未过期的 JWT。该行为列入故障实验。账户禁用和退出登录对既有 JWT 的影响遵循 2 小时有效期，前端和报告使用同一解释。

## 6. 验收与交付

- 合法用户注册后可登录，返回结构与前端一致；数据库只保存密码散列。
- 重复账户名、重复邮箱和并发重复注册不会产生重复用户。
- 错误密码、非法账户类型、缺失字段、篡改 JWT、过期 JWT 均被拒绝。
- `/users/me` 只返回当前用户资料，响应不包含密码和存储凭证。
- 不启动文件、分享、Redis、MinIO 时，认证服务仍可独立登录。
- 使用 auth_user 访问 file_db/share_db 时权限被拒绝。
- 肖国扬 与 狄东琛 联调同一 JWT，验证认证容器停止后文件 API 的预期行为。

交付源码、Dockerfile、auth_db 建表与迁移 SQL、环境变量说明、JWT 字段和验证约定、接口样例及验收记录。日志记录登录成功或失败的类别，过滤密码、完整令牌和邮箱等非必要个人信息。
