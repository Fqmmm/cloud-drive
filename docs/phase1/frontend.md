# frontend 需求文档

主责：肖国扬。范骐鸣 协助 Dockerfile 与 Nginx，刘骐语 负责端到端验收。关联：[总体方案](../plan.md)、[认证](auth-service.md)、[文件](file-service.md)、[分享](share-service.md)。

## 1. 页面范围与使用流程

复用现有 Vue 项目，保留登录、注册、个人文件、我的分享、匿名分享访问五类页面。登录后默认进入个人文件，顶部显示基础用户信息和退出入口。注册表单只创建个人账户，删除工作和团队账户选项。

个人文件页显示面包屑、文件名、大小、类型和上传时间，支持进入目录、返回上级、创建目录、重命名、上传、下载和永久删除。目录删除限制为空目录。显示总容量和已用容量，上传或删除成功后重新获取列表及配额；失败时保留当前列表并显示原因。上传中禁用重复提交按钮，下载使用二进制响应，保留原文件名。

我的分享页显示文件名、创建时间、有效期、状态和分享地址，支持创建、复制地址和取消。创建分享只允许选择一个普通文件，可选提取码，支持 1/7/30 天及永久。匿名访问页允许未登录用户打开；有提取码时提交校验后显示文件信息，下载时再次提交提取码。

退出登录清除本地 JWT 和用户缓存并回到登录页。下载失败的 JSON 错误需要从 Blob 中解析后提示，避免将错误内容保存成文件。非 JSON 的网关错误按 HTTP 状态显示通用提示，网络断开显示连接失败，不将 HTML 或错误正文当作正常下载文件保存。

## 2. 原前端清理清单

检查 `frontend/src/api/`、路由、菜单、状态管理及页面挂载时的请求。移除团队、邀请、权限角色、会员、私密空间、回收站和系统管理入口及调用。去掉首页对团队列表、会员状态、访问统计的聚合请求；用户基础资料与配额分别读取。

已有 `config.ts` 将 API 根路径定义为 `/api/v1`，统一保留这一层。`utils/request.ts` 已识别字符串成功码 `00000`、Bearer JWT 和 Blob 响应，适配时保留协议并补齐 Blob 错误处理。旧的路径下载、目录分享、SSE 下载进度、复制移动按钮随首版范围一并清理。直接访问已移除页面时跳转个人文件页或显示页面不存在。

## 3. API 与路由

| 页面动作 | 目标接口 |
|---|---|
| 注册、登录 | `POST /api/v1/auth/register`、`POST /api/v1/auth/login` |
| 基础资料 | `GET /api/v1/users/me` |
| 列表、上传、下载、删除 | `/api/v1/files`、`/api/v1/files/{id}/download`、`DELETE /api/v1/files/{id}` |
| 文件重命名 | `PUT /api/v1/files/{id}/rename`，首版新增 |
| 目录管理 | `/api/v1/directories`、`/api/v1/directories/{id}/rename`、`DELETE /api/v1/directories/{id}` |
| 配额 | `GET /api/v1/quota` |
| 分享管理 | `/api/v1/shares`、`DELETE /api/v1/shares/{id}` |
| 匿名分享 | `GET /api/v1/s/{token}`、`POST /api/v1/s/{token}/verify`、`POST /api/v1/s/{token}/download` |

表中新增和调整的路径由 肖国扬、狄东琛 同步实现。JSON 使用 `{code, msg, data}`；上传字段为 `file`，查询参数 `parentId=0` 表示根目录。前端路由模式沿用项目已有配置：hash 模式分享链接包含 `/#/`；history 模式配置 `try_files`，且分享 URL 生成方式与之保持一致。

Nginx 使用总体方案的路由表，精确覆盖集合路径和子路径，转发时保留 `/api/v1` 前缀和 Authorization 请求头。`/internal/` 与后台健康接口不转发；未知 `/api/` 路径返回 404，避免被 SPA 回退误判为成功页面。Nginx 自身的 404/413/502/504 可以保留默认响应体，由前端按状态兜底，无需统一配置 JSON 错误页。

## 4. 镜像与配置

前端采用 Node 构建、Nginx 运行的多阶段镜像，使用仓库锁文件对应的包管理器，运行镜像只携带产物和 Nginx 配置。部署时浏览器请求同源入口，构建产物中不出现 `auth-service`、`mysql` 等内部地址。

| 配置 | 基线 |
|---|---|
| 宿主机访问 | `http://localhost:8080`，端口可由环境配置 |
| Nginx 监听 | 容器内 80 |
| 请求体限制 | `105m`，业务单文件限制为 100 MiB |
| API 连接/读取超时 | 连接 3 秒，普通 API 读取 15 秒，文件传输读取 120 秒 |
| 页面健康探测 | `GET /healthz` 返回静态 200 |
| 分享页面 | 设置 Referrer-Policy，避免分享凭证随外部跳转泄露 |

范骐鸣 验证后端容器重建后的域名解析和 Nginx 恢复方式。基础方案允许更新后显式 reload Nginx，并把该步骤写入部署脚本；双副本实验另行验证请求分发。访问日志不记录请求体、Authorization 和提取码。

## 5. 验收

| 用例 | 通过条件 |
|---|---|
| 首次访问与刷新 | 登录页可用；登录后刷新仍能进入正确页面 |
| 业务闭环 | 从注册到上传、分享、匿名下载和取消分享连续完成 |
| 文件操作 | 中文和空格文件名可显示、下载；重命名冲突有提示；非空目录删除被拒绝 |
| 错误处理 | 超限、超额、无效 JWT 和分享错误码有可读提示，非 JSON 网关错误按 HTTP 状态兜底；不另增实验场景 |
| 范围精简 | 页面无旧功能入口，网络面板无团队、会员、私密空间请求 |
| 网络边界 | 浏览器只访问 frontend，内部路由被拒绝，未知 API 不回退为 SPA 成功页，网关错误正文不直接展示给用户 |

交付页面源码、API 类型定义、Dockerfile、Nginx 配置、页面与 API 对照表、构建命令及浏览器验收记录。肖国扬 对整体前端结果负责，范骐鸣 提交部署部分，刘骐语 保存业务操作证据。
