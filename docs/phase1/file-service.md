# file-service 需求文档

负责人：B。关联：[总体方案](../plan.md)、[分享服务](share-service.md)、[MySQL](mysql.md)、[MinIO](minio.md)。

## 1. 职责和首版范围

文件服务统一管理个人目录、文件元数据、固定配额和 MinIO 对象。用户身份从本地验证后的 JWT 读取；浏览器传入的 userId 不参与授权。每次读取和修改都按当前用户及文件 ID 限定范围。

首版支持列表、创建目录、文件和目录重命名、空目录删除、上传、下载、永久删除。根目录以 `parentId=0` 表示。目录必须属于当前用户，不能将普通文件作为父目录；同一用户、同一父目录内名称唯一，文件与目录共用名称空间。非空目录删除返回 409，前端提示先删除内容。

每用户默认容量为 10 GiB，单文件上限为 100 MiB。环境变量可调整数值，验收和实验记录实际值。目录不占容量；用户可见的活动文件按文件大小计费。首版每次上传生成独立随机对象键，保留已有对象表结构时采用一文件一对象的映射。去重、回收站、移动复制、搜索和递归目录删除留待扩展。

## 2. 目标 API

下表是第一版接口契约；文件重命名为新增接口，其余接口在现有实现上精简。

| 方法与路径 | 输入 | 结果 |
|---|---|---|
| `GET /api/v1/files` | `parentId`，默认 0 | `{breadcrumb, items}`，目录下文件和子目录 |
| `POST /api/v1/files` | multipart 字段 `file`，查询参数 `parentId` | 新文件 ID、名称、大小等 |
| `GET /api/v1/files/{id}/download` | JWT | 二进制流，包含 Content-Disposition |
| `PUT /api/v1/files/{id}/rename` | `{name}` | 更新后的文件信息 |
| `DELETE /api/v1/files/{id}` | JWT | 文件逻辑失效，安排对象清理 |
| `GET /api/v1/directories` | `parentId` | 当前层子目录，按页面实际需要保留 |
| `POST /api/v1/directories` | `{name, parentId}` | 目录 ID 和名称 |
| `PUT /api/v1/directories/{id}/rename` | `{name}` | 更新后的目录信息 |
| `DELETE /api/v1/directories/{id}` | JWT | 删除空目录 |
| `GET /api/v1/quota` | JWT | `{totalBytes, usedBytes}` |
| `GET /internal/v1/files/{id}` | `ownerId`、内部凭证 | `{id, ownerId, originalName, fileSize, mimeType, isDirectory}` |
| `GET /internal/v1/files/{id}/content` | `ownerId`、内部凭证 | 活动普通文件的二进制流 |
| `GET /health/live`、`GET /health/ready` | 容器探测 | 存活/依赖就绪 |

列表项沿用 `id, originalName, fileSize, mimeType, createTime, isDirectory, parentId`。统一补齐前端 TypeScript 类型；`fileUrl` 不返回私有桶地址。下载使用受控 API。

私有 API 验证 JWT。内部 API 使用 `X-Internal-Token`，常量时间比较凭证，并验证 ownerId 与文件归属；其 ownerId 是分享服务在完成业务校验后传入的受信请求字段。内部元数据接口只返回归属匹配的活动记录：200 表示记录可用，已删除、不可见或不存在均返回 404，分享服务通过 isDirectory 拒绝目录分享，无需另设 status 枚举。内部接口拒绝缺失或错误凭证，Nginx 不转发这些路径。MinIO 桶保持私有。

资源不属于当前用户或已失效时统一返回 404。名称冲突、非空目录为 409，单文件过大为 413，配额不足使用明确业务码与 409，存储依赖失败为 503。文件传输开始后若中断，连接会失败；客户端按下载失败处理，不在二进制尾部拼接 JSON。

## 3. 数据模型与并发要求

file_db 保存个人文件/目录、物理对象映射和用户配额。沿用 `sys_file`、`sys_file_object`、`user_quota` 时，清除团队和会员字段的运行依赖，记录保留字段的含义。文件记录至少包含用户、父目录、名称、大小、类型、对象键、活动状态、清理状态和创建时间。

配额按 userId 唯一，首次查询或上传时幂等初始化。上传提交时锁定或原子更新该用户配额，确认 `usedBytes + fileSize <= totalBytes`，在同一事务内写入活动文件记录并增加用量。两个并发上传不能同时通过旧用量检查而超额。同名约束应覆盖活动记录；软删除后的重名处理方式在建表 SQL 中明确。

上传流程：校验身份、父目录和文件大小；以随机对象键写入 MinIO；在数据库事务中重新检查名称和配额并提交元数据。提交失败时清理刚写入的对象。清理失败时持久记录对象键和原因，交由同一套可重试清理任务处理。基础版提供按待清理记录查询和重试的脚本；全量孤儿对象扫描列为扩展，扫描结果需核对数据库引用并避开正在上传的对象。

永久删除在本地事务中将文件标为不可见并扣减配额，重复删除不会重复扣减。同时持久记录待清理对象，由文件服务的可重试任务删除 MinIO 对象；对象已不存在也视为清理成功。MinIO 中断时保留待清理状态，恢复后继续。删除后的文件立即对下载和分享不可见。

## 4. 与其他服务的边界

文件服务只访问 file_db 和 MinIO，不查询 auth_db。原文件实现中的 `SysUserMapper`、会员与下载限速逻辑需移除；基础展示名采用现有文件记录或由前端基础资料展示，避免为列表逐项调用认证服务。

share-service 调用内部接口确认文件所有者和有效状态，再通过内容接口中转下载。文件服务不读取分享表；取消分享在分享服务生效，删除文件在文件服务生效。内部接口对普通文件生效，目录分享请求被拒绝。

单用户配额和文件写入使用本地事务，MinIO 操作使用补偿及清理状态。B 提供待清理记录的查看和重试方法，D 在故障与持久化实验中验证。

## 5. 运行配置与迁移检查

| 配置项 | 基线 |
|---|---|
| HTTP | 容器内 8080 |
| 数据库 | `mysql:3306/file_db`，file_user |
| 对象存储 | `http://minio:9000`，私有桶 `cloud-drive` |
| 配额/单文件 | `DEFAULT_QUOTA_BYTES=10737418240`；`MAX_FILE_BYTES=104857600` |
| 服务鉴权 | JWT 参数与 A 保持一致；单独 INTERNAL_API_TOKEN |
| 内部请求 | 普通查询有限超时；存储连接 3 秒、读取 120 秒，实际值记录 |

Spring multipart、Nginx 和业务大小限制协调配置，请求总上限留出 multipart 开销。桶由文件服务启动时幂等检查和创建，数据库/存储暂不可用时就绪返回非 200 并进行有界重试；存活检查保持独立。业务恢复后就绪恢复，进程可继续服务。

B 检查现有 `oss`、`quota`、`admin`、`team` 交叉引用，删除旧回收站定时任务和团队文件入口，防止后台任务误清理课程文件。仅首版文件服务单实例运行，扩容实验选择分享服务。

## 6. 验收与交付

| 场景 | 通过条件 |
|---|---|
| 文件闭环 | 创建目录、上传、重命名、下载、删除成功；SHA-256 一致 |
| 用户隔离 | 用户 B 操作用户 A 的目录/文件均被拒绝，列表不泄露记录 |
| 并发与配额 | 并发上传不超额，同名冲突结果明确；失败上传不增加用量 |
| 删除 | 同一文件重复删除不重复扣额；MinIO 恢复后待清理对象被删除 |
| 内部接口 | 无凭证、错误 ownerId、目录和已删除文件均被拒绝 |
| 初次启动 | 新用户配额仅创建一次，私有桶自动就绪，无手工建表建桶步骤 |

交付源码、Dockerfile、file_db SQL、内部接口样例、配置说明、待清理查询与重试脚本、文件完整性与权限验收记录。
