# minio 需求文档

负责人：狄东琛。范骐鸣 接入 Compose，刘骐语 验证文件保存与重建。关联：[文件服务](file-service.md)、[持久化实验](../phase2/04-persistence.md)。

## 1. 存储范围与访问路径

MinIO 保存用户上传的原始文件，文件服务保存文件名、用户、目录和对象键等元数据。目录是数据库记录，不要求在 MinIO 创建对应实体目录。

固定使用私有桶 cloud-drive，文件对象键由文件服务生成随机标识。用户上传的原文件名只作为元数据和下载文件名，避免直接拼接为对象键。下载内容由文件服务读取，个人下载经 Nginx，分享下载经分享服务中转。

浏览器不直接访问 MinIO，不获得访问密钥或长期对象 URL。share-service 不持有 MinIO 配置。桶默认禁止匿名列举和读取，公开分享的授权由分享服务承担。

## 2. 容器配置

| 项目 | 要求 |
|---|---|
| 服务名 | minio |
| API | 容器内 9000，文件服务地址 `http://minio:9000` |
| 控制台 | 容器内 9001；调试覆盖配置可发布到 127.0.0.1 |
| 数据卷 | minio_data 挂到 `/data` |
| 镜像 | 选择能在演示环境实际拉取和运行的固定标签，记录 digest |
| 凭证 | 环境注入 MINIO_ROOT_USER、MINIO_ROOT_PASSWORD；file-service 的访问配置与之对应 |
| 重启 | unless-stopped，手动停止后由操作者启动 |

课程使用独立的本地 MinIO 实例，首版文件服务可使用该实例的专用管理员凭证完成桶初始化和对象读写，凭证只注入 minio 与 file-service。后续改用桶级应用账号时，需补齐自动创建及授权流程，并复验一键部署。

就绪探测使用所选版本实际支持的健康端点；curl/wget 不一定随镜像提供，狄东琛 需检查镜像并选用可执行的探测方式。数据库和 MinIO 均就绪后，文件服务开始自己的依赖初始化。

## 3. 桶初始化和对象生命周期

文件服务启动时检查并创建 cloud-drive，已存在时继续运行。桶权限保持私有，文件服务就绪前确认可访问桶。此方式保持基础系统六个常驻容器；临时管理工具按需要一次性运行并退出。

对象上传成功后才尝试提交元数据，失败补偿和对账由文件服务负责。文件删除先使记录不可见，再处理持久化的待清理对象。MinIO 短时中断后，任务能够重试；对象已经不存在时，重复删除视为成功。狄东琛 提供按对象键检查存在性和大小的方法，供 刘骐语 对照数据库记录。

首版每个文件对应独立对象，逻辑用量按文件字节计算。若启用去重，必须增加引用计数或等价引用检查，并补充“删除一个引用不破坏另一个文件”的验收。首版不启用生命周期自动清理规则，避免按对象年龄清除仍被引用的文件。

## 4. 故障和数据保护

MinIO 停止时，文件列表可继续从数据库读取；上传、下载和匿名分享下载返回可控错误。文件服务就绪状态可显示依赖异常，存活检查不随之失败。MinIO 恢复后重试连接，原文件无需重新上传。

重建容器保持 minio_data 卷和挂载路径不变，验证对象仍存在。数据卷保留和备份恢复分别验证：前者重用原数据，后者将停写窗口内备份的对象恢复到新卷。

备份使用与所选镜像兼容的对象管理工具，对私有桶列举、复制并生成对象清单。工具凭证以环境或受控配置提供，输出过滤密钥。刘骐语 执行恢复后，以用户实际下载的文件 SHA-256 作为内容完整性的主要依据。

## 5. 验收

1. 全新环境自动创建私有桶，用户从页面上传和下载成功。
2. 中文、空格文件名与二进制文件下载后内容一致，对象键与用户文件名分离。
3. 匿名直接读取或列举桶被拒绝，前端响应不暴露密钥和内部对象地址。
4. 重建 MinIO 容器且保留卷后，不同大小文件均能下载并通过 SHA-256。
5. MinIO 短时不可用时错误有界，恢复后上传下载重新成功。
6. 文件删除后对象最终清理，失败任务可检查、重试；不影响其他用户文件。
