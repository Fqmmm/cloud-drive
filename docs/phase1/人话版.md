可以把这个网盘理解成一家提供“存文件、取文件、发分享链接”服务的小店。**六个容器就是六个分工明确的工作单元**，每个里面运行一套程序。

**1. frontend：用户看到的网页，也是所有请求的入口。**

你打开网盘后看到的登录页、文件列表、上传按钮、分享页面，都由它提供。

你点击按钮后，它还负责把请求转给对应的后端服务。例如，点击登录就转给认证服务，点击上传就转给文件服务。

这个容器里同时放 Vue 构建出的页面和 Nginx，**前端与 Nginx 合起来算一个容器**。

**2. auth-service：负责确认“你是谁”。**

它处理注册、登录和基础用户资料。

登录成功后，它发给浏览器一个 JWT，可以理解为一张有有效期、能够验证真伪的通行证。之后浏览器带着它访问文件服务，文件服务就知道该打开哪个用户的空间。

其他服务可以自己验证通行证，不必每次都回头问认证服务。

**3. file-service：负责管理个人文件。**

你上传、下载、重命名、删除文件，创建目录、查看剩余容量，都是它处理。

它还负责检查权限和规则：这个文件是不是你的？容量够不够？名称有没有重复？是否超过单文件大小限制？

**它管理文件，但实际文件内容交给 MinIO 保存，文件记录交给 MySQL 保存。**

**4. share-service：负责管理“别人凭什么能下载你的文件”。**

你创建分享链接、设置提取码和有效期、取消分享，都由它处理。

别人打开链接时，它检查链接是否存在、有没有过期、是否已取消、提取码是否正确。检查通过后，它再找文件服务获取文件，转给接收者。

所以，收到分享链接的人可以下载指定文件，却不能浏览你的整个网盘。

**5. mysql：负责保存各种“记录”。**

它保存用户账户、文件名称、文件大小、目录关系、已用容量，以及分享链接、有效期等信息。

例如，它记录：

> 用户张三有一份“实验报告.pdf”，大小为 2 MiB，放在“课程资料”目录，实际内容对应某个对象编号。

PDF 的实际内容放在 MinIO。MySQL 容器内部划分三个逻辑数据库，分别给认证、文件、分享服务使用，**仍然只算一个容器**。

**6. minio：负责保存实际的文件内容。**

PDF、照片、压缩包、视频等文件的实际内容都存在这里，可以把它理解为文件仓库。

它按对象编号保存和读取内容；“文件属于谁、显示什么名字、谁有权下载”等规则，由文件服务和分享服务处理。

你上传文件时，六个容器这样配合：

1. **frontend** 显示上传页面，把请求交给文件服务。
2. **file-service** 验证登录通行证，检查权限、大小和容量。
3. **minio** 保存文件的实际内容。
4. **mysql** 保存文件名称、归属、大小和存放位置等记录。
5. **frontend** 更新列表，让你看到新文件。

如果再创建分享，**share-service** 就参与进来；**auth-service** 主要在注册和登录时工作，不会每次上传都被调用。

最后，Docker Compose 负责把这六个工作单元一起启动、连通，并配置好数据存放位置。**Compose 是管理这六个容器的工具，本身不再占一个容器。**
